# ADR 0005: Web 认证与共享 HTTP 契约

- Status: Accepted
- Date: 2026-10-13

## 背景

Web 登录页是首个实际消费 API 的客户端功能，满足架构中创建共享契约包的条件。API 已有邮箱密码登录、当前会话和退出接口，以及 Cookie、来源校验、限流和服务端撤销机制。

## 决策

- 创建 `packages/contracts`，以 `@workspace/contracts/auth` 暴露 Zod 4.4.3 运行时模式和推导类型。该版本已由仓库采用，不引入另一个模式库。
- API 的登录输入通过共享模式验证；输出显式映射到共享会话响应。业务用户与会话类型继续由各自模块所有。
- Web 通过集中 HTTP 客户端访问 API，使用 `credentials: include`、禁用认证缓存、限定请求时长并验证响应。页面不读取或持久化 Cookie 中的令牌。
- 保留现有来源校验、限流、HttpOnly、SameSite 和生产 Secure Cookie 规则。变更本地预览端口通过启动配置完成，不放宽认证策略。
- 共享包输出 CommonJS 与类型声明，同时支持现有 NestJS 与 Next.js。包当前仅供仓库内部使用，不独立发布；契约变更同步更新所有实际消费者并运行端到端测试。
- 登录成功进入最小账户会话页面，提供会话确认与退出入口。邀请发送、邀请接受、密码恢复和钱包业务不在本次实现范围内。

## 结果

首个真实传输契约拥有明确的共享边界，避免客户端导入 API 源码或重复维护认证类型。Web 可呈现可靠的登录状态和中文错误反馈；API 仍是认证与授权的唯一权威。Mobile 的凭据传输决策继续独立待定。
